01 / PROJECT NOTES

Cybersecurity Toolkit

A collection of security utilities that run in the browser. The first module is a password generator. This page records what is implemented so far and how it works.

In development HTML · CSS · JavaScript

What works now

The first version is ready to test locally in XAMPP. It generates passwords from 8 to 64 characters, using any combination of uppercase letters, lowercase letters, numbers and symbols.

  • Every selected character type appears at least once.
  • Similar characters such as O, 0, I, l, 1 and | can be excluded.
  • The result can be shown, hidden and copied.
  • Changing the settings clears the previous result until a new password is generated.

How generation works

  1. The selected types are combined into a character pool.
  2. crypto.getRandomValues() supplies random bytes from the browser.
  3. Byte values that would create an uneven mapping are discarded before characters are selected.
  4. A complete candidate is rejected if it is missing any selected type.

The result is sampled uniformly from passwords that meet the settings. The search-space figure counts those possible results; it is not an estimate of how long a password would take to crack.

Implementation choices

Keep passwords on the device

The app has no server, remote scripts or password history. Generation happens in page memory. Copying deliberately places the result on the system clipboard.

Separate the logic from the interface

js/password-generator.js handles character pools, generation and search-space calculation. js/main.js handles the form and buttons. This lets the generator be tested without the page.

Handle clipboard restrictions

If automatic copying is unavailable, the app selects the result so it can be copied manually. It never reports a successful copy if the clipboard operation fails.

Checks included

The generator has Node.js tests covering all combinations of character types, minimum and maximum length, exclusions, invalid inputs, rejected random bytes and candidates missing a selected type.

The checks also verify the search-space calculation and that generation stops with an error when secure randomness is unavailable.

Next steps

Add password analysis, then IP analysis and checks for suspicious URL patterns. Screenshots and further testing notes will be added as the interface is reviewed.
